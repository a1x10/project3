# Безопасность

STELLA выполняет реальные действия на вашей машине, поэтому защита встроена в каждый слой. Это не песочница: процессы, запущенные агентом, работают с правами вашего пользователя. Для недоверенного кода используйте контейнер/VM.

## Модель угроз

1. **Ошибки или «инициатива» модели** — удаление файлов, деструктивные git-операции, установка пакетов.
2. **Prompt injection** — инструкции внутри файлов, веб-страниц, вывода команд, ответов MCP.
3. **Вредоносный репозиторий** — проектные хуки/MCP-серверы/плагины, которые выполнились бы при открытии папки.
4. **Утечка секретов** — передача `.env`, ключей, credentials в модель или логи.

## Защиты

| Механизм | Где |
|---|---|
| Режимы и правила разрешений, подтверждение пользователя, журнал решений | `permissions/engine.ts`, `/permissions log`, `audit.jsonl` |
| Анализ shell: разбор цепочек `; && \|\| \|`, обнаружение `$()`, обратных кавычек, `<()`, `bash -c`, `eval`, `xargs`, `find -exec`, `node -e`, перенаправлений записи | `permissions/shell.ts` |
| Allow-правило должно покрыть каждую часть цепочки и не действует на подстановки/вложенные интерпретаторы | `ruleMatches` |
| Катастрофические команды (`rm -rf /` и `~`, `mkfs`, `dd of=/dev/…`, fork-бомба, форматирование диска, force-push в main…) блокируются даже в bypass | `CRITICAL` |
| Высокий риск: удаление, `sudo`, `curl … \| sh`, установка пакетов, push/reset --hard/clean, chmod/chown, kill, системные настройки, удалённый доступ | `HIGH` |
| Пути: нормализация, NUL-байты, `..`, разрешение symlink (включая ещё не существующие файлы через ближайшего существующего предка), проверка рабочей области | `security/paths.ts` |
| Запрет записи в системные каталоги (`/etc`, `/usr`, `C:\Windows`, …) в любом режиме | engine |
| Конфиденциальные файлы: Read, `@`-упоминания и shell-команды, ссылающиеся на них, требуют подтверждения; Grep их не показывает | `DEFAULT_CONFIDENTIAL`, `permissions.confidential` |
| Read-before-edit и проверка, что файл не изменился с момента чтения; атомарная запись | `tools/fs.ts` |
| Чекпоинты перед любым изменением, `/rewind` с отказом перезаписывать ручные правки пользователя | `recovery/checkpoints.ts` |
| Доверие к папке: проектные хуки, MCP-серверы и плагины отключены до `/trust` | `runtime.ts` |
| Команды Git — массивы аргументов, без shell; `push`, удаление веток и force-операции не предоставляются инструментами | `tools/git.ts` |
| Секреты: маскирование в аудит-логе и выводе настроек, запрет записи в память, credentials в отдельном файле с правами 600 | `utils/redact.ts`, `config/settings.ts` |
| Контроль процессов: таймауты, kill всего дерева (process group / `taskkill /T`), остановка фоновых процессов при выходе, stdin закрыт | `tools/process.ts` |
| cwd оболочки сохраняется только внутри рабочей области | `tools/shell.ts` |
| Системный промпт: содержимое файлов/веба/инструментов — данные, не инструкции | `agent/prompt.ts` |
| Субагенты не могут быть более разрешающими, чем сессия, и не могут порождать субагентов | `mostRestrictive` |

## Ограничения

- Статический анализ shell не является полноценной песочницей: программа, которую вы разрешили запускать (например, `npm test`), может сама делать что угодно. Разрешайте узкие команды.
- `bypassPermissions` и широкие правила (`Bash`) отключают большую часть защиты — используйте только в одноразовых окружениях.
- Сеть агента не фильтруется по IP: `WebFetch` запрашивает подтверждение в режимах кроме `auto`.
