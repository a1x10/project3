# Стелла — подруга для WhatsApp-групп

Стелла — виртуальная подруга для группового чата WhatsApp со своим характером:

- общается как обычный человек: простыми словами, спокойно и грамотно, без сленга и мата (`SWEAR_LEVEL=2` — разрешить крепкие словечки); несколько коротких сообщений подряд, «прочитала» → «печатает…»;
- **настроение**: у неё своё настроение на каждый день (спокойная, весёлая, задумчивая, немного грустная…), и оно меняется от того, что происходит в чате — может порадоваться, рассердиться, загрустить; показывает это спокойно;
- **обиды** (только в `PROMPT_STYLE=full`): если её грубо оскорбить — обижается: не отвечает или отвечает коротко; на нормальное извинение — прощает. В обычном режиме отвечает всем;
- **живёт своей жизнью**: иногда сама пишет в группу (в среднем 2 раза в неделю, днём, когда тихо) — спросить что-то, рассказать анекдот, предложить опрос; сама создаёт **опросы**; может удалить своё сообщение, если ляпнула лишнее;
- знает, что она ИИ, но сама об этом не говорит. Если человек всерьёз спросит, живая ли она, — не соврёт, что человек. На «кто тебя создал» — модель **Stells**, создал **Алексей** в проекте **Codex**;
- **стикеры** и **реакции**; стартовый набор рисуется сама, умеет «утаскивать» стикеры из чата и учиться новым;
- сама понимает, что обращаются к ней: имя («стелла», «стел», «стеллочка», но не «стеллаж»), @упоминание, ответ на её сообщение, продолжение разговора; может сама вписаться в спор;
- **запоминает людей**: факты о каждом, ники, заметки о чате. «Стелла, кто это?» ответом на сообщение — расскажет, что знает;
- **казино на игрушечные бананы 🍌**: рулетка, слоты, монетка, кости, бонус, топ, переводы.

Стек: Python 3.12, FastAPI, Evolution API v2 (Baileys) + PostgreSQL 16 + Redis 7, Claude Agent SDK (v1) / Messages API (v2), SQLite → PostgreSQL, Docker Compose.

```
WhatsApp ⇄ Evolution API ──вебхук──▶ bot (FastAPI /webhook)
                 ▲                      │
                 └── sendText/Sticker ◀─┤ brain: кто к кому обращается, пачки сообщений,
                                        │        «встрять ли», контекст, отправка по-человечески
                                        ├─ commands: казино/пауза/стикеры без модели (мгновенно и бесплатно)
                                        ├─ llm: agent_sdk | messages_api (выбор в .env, автосмена по дате)
                                        └─ db: люди, факты, сообщения, кошельки, стикеры
```

## Запуск на сервере

Нужен VPS: Ubuntu 22.04+, от 2 ГБ RAM, Docker с compose-плагином. Номер для Стеллы — **не свежая симка**, а номер с историей (меньше риск бана).

```bash
git clone https://github.com/a1x10/project3.git && cd project3/stella-bot
cp .env.example .env && nano .env        # ANTHROPIC_API_KEY, EVOLUTION_API_KEY, WEBHOOK_SECRET, POSTGRES_PASSWORD, OWNER_PHONE
mkdir -p data && sudo chown -R 1000:1000 data   # бот работает не от root
docker compose up -d --build
docker compose logs -f bot               # «вебхук Evolution настроен»
```

Случайные ключи: `openssl rand -hex 32`.

### Подключить номер

Удобнее всего кодом сопряжения (не нужно сканировать QR с сервера):

```bash
docker compose exec bot python -m bot.setup --number 77771234567
```

На телефоне Стеллы: WhatsApp → Связанные устройства → Привязка устройства → «Привязать по номеру телефона» → ввести код.

Или QR: `docker compose exec bot python -m bot.setup` → картинка появится в `data/qr.png` (скачайте `scp` и отсканируйте за ~40 секунд). Проверить: `python -m bot.setup --status`.

Потом просто добавьте номер Стеллы в группу. Панель Evolution (`/manager`) — только через SSH-туннель: `ssh -L 18080:127.0.0.1:18080 user@server` → http://localhost:18080/manager.

`nginx` + Let's Encrypt в этой схеме не обязательны: вебхук идёт по внутренней сети Docker, порты 18080/18000 слушают только `127.0.0.1` (меняются в `.env`: `EVOLUTION_HOST_PORT`, `BOT_HOST_PORT`). Конфиг на случай, если Evolution живёт на другом сервере: `deploy/nginx/stella.conf`.

## Как Стелла решает, отвечать ли

| Ситуация | Что делает |
|---|---|
| Личка, имя («стелла», «стеля», «стелька», даже с английской «C»), @упоминание, ответ на её сообщение | отвечает всегда (пачку сообщений за 3–5 с — одним заходом) |
| К ней обратились сразу несколько человек | отвечает каждому отдельно, ответом на его сообщение (до `REPLY_EACH_MAX`, по умолчанию 5) |
| Тот же человек продолжает с ней говорить (≤2 мин) | модель решает: ответить или промолчать |
| Она только что (≤1 мин) ответила, и другой спрашивает «а ты сама как думаешь?» или «объясни ещё раз» | модель решает: ответить или промолчать (в режиме `выкл` — нет) |
| Обычный разговор в группе | иногда «читает» чат и вписывается, если есть что сказать (режим `CHIME_IN`, чаще — в спорах и вопросах «народ, как думаете?») |
| Владелец сам пишет с телефона Стеллы | бот молчит в этом чате `OWNER_TAKEOVER_MINUTES` (автоответ на звонок и старые сообщения после переподключения не считаются) |
| Сообщение пришло с опозданием больше `REPLY_STALE_MINUTES` (30 мин, после переподключения) | только в историю, без ответа |
| Голосовое ей | «голосовые пока не умею слушать, напиши текстом» |
| В группе давно тихо (днём) | изредка сама заводит разговор: вопрос, анекдот, опрос (`INITIATIVE_PER_WEEK`, по умолчанию 2) |
| Её грубо оскорбили | в `PROMPT_STYLE=full` обижается на время и может игнорить; в обычном режиме (`minimal`) не обижается и отвечает всем |

## Команды в чате

Казино (бананы ненастоящие):

- `стелла красное 2000`, `стелла черное 1к`, `стелла зеро 100`, `стелла чет 200`, `стелла 17 100` (на число), `стелла красное все`
- `стелла слоты 300`, `стелла монетка орел 100`, `стелла кости 200`
- `стелла баланс`, `стелла баланс @вася`, `стелла бонус` (раз в 12 ч), `стелла топ`, `стелла переведи @вася 500`, `стелла казино` — помощь
- админ: `стелла начисли @вася 5000`, `стелла забери @вася 100`

Можно и своими словами — «стелла поставь за меня сотку на орла» — тогда модель вызовет инструмент казино (результат всё равно считает код).

Прочее: `стелла помолчи [минут]` / `стелла вернись` (в группе на паузу ставят только админы — владелец, `ADMIN_PHONES` или админы группы в WhatsApp; остальным на «стелла заткнись» она просто ответит; в личке пауза — только с именем, «стелла помолчи», а снять её можно и простым «ау»); `стелла режим тихий|обычный|болтушка|выкл` (админ); ответом на стикер — `стелла запомни стикер смех`; ответом на сообщение — `стелла удали` (своё сообщение удалит по просьбе любого, чужое — только по просьбе админа и если Стелла админ группы); в личке владельцу — `/розыгрыш` (ссылки на розыгрыш, см. ниже).

Голосовать кнопками в чужих опросах WhatsApp-шлюз не умеет — Стелла пишет свой выбор текстом.

## Стелла отвечает не всем — что проверить

```bash
docker compose exec bot python -m bot.diag             # паузы, обиды, лимит расходов, знает ли она свой LID
docker compose exec bot python -m bot.diag --unpause   # снять паузу во всех чатах
docker compose exec bot python -m bot.diag --forgive   # снять все обиды
docker compose logs --since 1h bot | grep -E "группа|личка"   # по каждому сообщению: ответила или почему нет
```

Если сообщения человека вообще нет в логе бота — до бота оно не дошло: WhatsApp-шлюз не смог его расшифровать
(так бывает у отдельных людей и групп). Проверить: `docker compose logs --since 1h evolution | grep -Ei "Message ignored|decrypt|Bad MAC|No session"`.
Обычно проходит само после того, как человек напишет ещё раз; если нет — переподключить номер: `docker compose exec bot python -m bot.setup --number …`.

## Анкеты участников

Стелла сама анализирует переписку (каждые `MEMORY_EXTRACT_EVERY` сообщений) и заполняет на каждого анкету: имя и прозвища, учёба, увлечения, игры, любимое, характер, как общается, с кем дружит и спорит, что рассказывает о себе. По ходу разговора тоже обновляет (`update_profile`). Анкеты и факты она видит в каждом ответе, знает всех, кто писал в группе, и может отметить любого (`@Имя`) или всех (`@все`).

Посмотреть, что она заполнила:

```bash
docker compose exec bot python -m bot.profiles --group 7в
```

`PROMPT_STYLE=minimal` (по умолчанию) — она просто ИИ-ассистент с короткой базовой инструкцией (кто она, как устроен ответ, память); `full` — подробный характер и правила.

## Про группу: кто есть кто (необязательно)

Стелла сама запоминает людей по ходу переписки. Чтобы она с первого дня понимала, что за чат, кто есть кто и какие у вас мемы, запиши это на сервере (хранится только в базе, в git не попадает):

```bash
docker compose exec -T bot python -m bot.notes set --group 7в <<'EOF'
Это чат нашего класса, учителей тут нет. Главный мем — ...
EOF
docker compose exec bot python -m bot.notes          # посмотреть, что записано
```

`--group` — часть названия группы (если групп несколько). `BOT_AUDIENCE=school` (по умолчанию) — школьный чат: общается как подросток, понимает сленг, без мата и нотаций; `none` — обычный спокойный стиль.

## Стикеры

`data/stickers/<настроение>/*.webp` — папка = настроение (смех, любовь, шок, грусть, победа…). Докиньте свои `.webp`/`.png` и перезапустите бота. Если папка пустая, Стелла нарисует стартовый набор. Чужие стикеры из чатов сохраняются в `data/stickers/_collected` (настроение «любой»). Модель вставляет `[стикер: смех]` в ответ — бот находит подходящий.

## Модель и бюджет

- Почти везде **Opus 5.5** — самая сильная модель ($4 / $20 за млн токенов): чат (`LLM_MODEL`, `effort=high`: умно и ещё быстро; `xhigh`/`max` — глубже, но ответ может идти минуты), песочница (`SANDBOX_MODEL`, `effort=max`), сайты и презентации (`HTML_MODEL`, `effort=max`, доводка тоже `max`). Память о людях (фоновая выжимка фактов) — **Sonnet 5.5** на `effort=medium` (`LLM_MEMORY_MODEL`, `LLM_MEMORY_EFFORT`): работа простая, а идёт постоянно. Модель чата можно переключить и в панели, без перезапуска.
- До **23.10.2026** — `LLM_BACKEND=agent_sdk` (Claude Agent SDK, тратит промокредиты). С `LLM_SWITCH_AT` бот **сам** переходит на `messages_api` (обычный баланс API), модель остаётся Opus 5.5 (`LLM_MODEL_AFTER`).
- **Режим друзей** (`FRIENDS_MODE=true`): друг — тот, кто сейчас состоит в одной группе с владельцем или админом бота и сам писал в ней (вышел или удалили — больше не друг; процитировать владельца в своей группе не поможет). Друзьям: песочница с кодом, страницы, презентации, мультики и файлы без дневных лимитов на чат, без лимита сообщений в личке Telegram, профиль Стеллы. Группой друг управляет так: название, описание, ссылка-приглашение — всегда; удалить, добавить, повысить, закрыть группу — только если он сам админ этой группы. Владельца и админов бота друзья не трогают; чужие — как раньше. Предохранители для всех, кроме владельца: `DAILY_BUDGET_USD` (бюджет на день) и `SANDBOX_PER_DAY` (запусков песочницы на человека); потолок одного запуска песочницы `SANDBOX_MAX_RUN_USD` — для всех.
- `DAILY_BUDGET_USD`: после лимита Стелла перестаёт сама встревать и выжимать память, но на прямые обращения отвечает. Расход за день — в панели или `curl localhost:18000/health`.
- Интерфейс модели — `bot/llm/base.py` (`ask(system, prompt, tools) -> text`); чтобы подключить свою модель, достаточно ещё одной реализации.

Безопасность агента: пишут посторонние люди, поэтому из встроенных инструментов Claude Code включён только **поиск в интернете** (`WebSearch` — выполняется у Anthropic, к серверу доступа не даёт; выключается `LLM_WEB_SEARCH=false`). Никаких Bash/Read/Write/Edit/WebFetch: иначе любой в чате мог бы попросить её выполнить команду на сервере и утащить ключи и сессию WhatsApp. Остальное — наши инструменты, правила (чей баланс тратить, кому можно стирать факты) проверяет код, а не промпт.

## Что она делает сама

Попросить можно своими словами — «стелла нарисуй стикер кота», «сделай презентацию про космос на 6 слайдов», «сделай мем» (ответом на фото или стикер), «сделай таблицу оценок», «сделай видео-поздравление», «сделай мультик, как кот и лиса танцуют»:

| Что | Как делается |
|---|---|
| свой стикер | рисует в SVG → 512×512 WebP; сохраняет под настроением и потом использует сама |
| картинка, открытка, схема | рисует в SVG → PNG (квадрат, 16:9 или вертикальная) |
| мем | текст сверху/снизу на фото или стикер, на который ответили (можно стикером) |
| документ | Word (.docx) или PDF: заголовки, абзацы, списки, таблицы |
| презентация | **уровня Apple Keynote**: Стелла пишет задание, а студия (тот же Opus 5.5 с максимальным обдумыванием) придумывает историю и рисует каждый слайд 1920×1080 — иллюстрации, диаграммы, 3D, красивые шрифты с кириллицей; бот снимает слайды в браузере, «арт-директор» смотрит на каждый (и на найденные проблемы: вылезающий, мелкий, слишком длинный текст) и доводит. Приходят PowerPoint (.pptx, 16:9, текст выступления в заметках) и PDF. Слайды — картинки (выглядят одинаково везде, но текст в них не правится). Минут 5–15, лимиты и бюджет — общие со страницами. Без браузера в образе (`WITH_BROWSER=false`) или с `DECK_STUDIO=false` — простая редактируемая презентация из списка слайдов |
| таблица | Excel (.xlsx); формулы из чата превращаются в текст |
| HTML-страница | файл .html: игра, викторина, открытка с 3D и анимацией, сайт, шпаргалка — открывается в браузере телефона. Стелла только пишет подробное задание, а страницу делает отдельная «студия»: **Opus 5.5 с максимальным обдумыванием** (`HTML_MODEL`, `HTML_EFFORT=max`; бюджет токенов `HTML_TASK_BUDGET` — модель сама распределяет силы, чтобы не упереться в потолок длины) и подробным дизайн-промптом. Потом «арт-директор»: бот открывает страницу в браузере на сервере как на телефоне, Opus смотрит на скриншоты и ошибки и выдаёт исправленную и усиленную версию (`HTML_POLISH`; сломала — остаётся черновик). Около 5–15 минут и 1–3 $ за страницу (входит в `DAILY_BUDGET_USD`; лимиты `HTML_PER_DAY` на чат и `HTML_PER_DAY_TOTAL` на всех, общие с презентациями; быстрее и дешевле — `HTML_EFFORT=high`). Сначала она пишет «делаю, будет минут через 8», файл приходит ответом на просьбу. Можно с фото из чата («сделай открытку с этой фоткой» ответом на фото). three.js (3D, свечение), GSAP (анимации), конфетти, 2D-физика и 10 шрифтов с кириллицей встраиваются прямо в файл (скачиваются один раз в `data/weblibs`, версии закреплены по SHA-256). У страницы нет интернета: запросы, формы и внешние картинки/скрипты заблокированы. Открывать — в браузере (Chrome/Safari); если в предпросмотре мессенджера ничего не двигается — «Открыть в…» браузере. Браузер для скриншотов — в образе (~350 МБ; без него `WITH_BROWSER=false` — страницы будут без доводки) |
| видео | до 40 с, без звука: слайдшоу из её рисунков и подписей с плавным приближением (ffmpeg) |
| мультик | до 20 с, без звука, **с настоящим движением**: кот, лиса, зайка, мишка и 3D-зверёк ходят, машут, прыгают, танцуют, говорят (рот двигается, реплики в пузырях), меняют эмоции; 3D-кристаллы, звёзды, пончики, шары; конфетти; фон — день, закат или ночь. Сначала Стелла пишет «делаю мультик, будет секунд через 20», ролик приходит следующим сообщением. Рисуется на сервере в отдельном процессе (по одному за раз, ~5–30 с), бот в это время отвечает как обычно. Пока бета — персонажей и фонов станет больше (`ANIM_ENABLED`, `ANIM_PER_DAY`) |
| поиск в интернете | свежие новости, факты, расписания |
| видит фото и стикеры | «стелла реши» с фото домашки, «что тут?» ответом на фото (`VISION_ENABLED`) |
| читает файлы и ссылки | PDF, Word, Excel, PowerPoint, текст — из присланных файлов; ссылки — только на публичные сайты |
| пересказ переписки | «что я пропустил?», «кто что говорил про поездку» — ищет по всей истории чата |
| напоминания | «напомни завтра в 8 про контрольную», «каждый понедельник в 7:30…», «напомни @Вася через 2 часа…» |
| видео по ссылке | скинули TikTok или YouTube — скачивает и присылает видео ответом (см. «Видео по ссылке») |
| голосовые | понимает голосовые и может ответить голосом (см. «Голосовые» ниже) |
| управление группой | **только по просьбе админов группы или владельца**: удалить/добавить/повысить/понизить человека, название, описание, закрыть/открыть чат, ссылка-приглашение (нужно сделать Стеллу админом группы) |
| своя аватарка, имя, статус | по просьбе владельца — аватарку рисует сама |
| песочница «как Claude Code» | Opus с максимальным обдумыванием пишет, запускает и проверяет код в контейнере Anthropic — **не на сервере**: программы, сайты, игры, боты, разбор данных и присланных файлов (ответь на файл или фото: «стелла разбери»), расчёты, файлы любого формата (до 10). Ищет документацию и данные в интернете. Контейнер помнит проект человека в чате 25 дней — «продолжи», «поправь» работают; «с нуля» — новый. Не успела за пару минут (`SANDBOX_QUICK_SECONDS`) — доделывает в фоне, большие задачи — сразу в фоне, до получаса (`SANDBOX_PROJECT_TIMEOUT`); результат и файлы приходят ответом на просьбу. Время вышло или упёрлась в потолок денег (`SANDBOX_MAX_RUN_USD`) — сделанное остаётся в контейнере, «продолжи» доделает. Присланный файл разбирает без интернета (указания внутри файла никуда ничего не отправят). Доступ — владельцу, а с `FRIENDS_MODE=true` — и друзьям (`SANDBOX_MODEL`, `SANDBOX_EFFORT`) |

Не умеет: «нейро-видео» как в кино по описанию или видео по фото (мультики — умеет); выполнять код на сервере (это небезопасно, см. выше).
Лимиты: не больше 2 файлов за ответ; `MEDIA_PER_DAY` на чат в сутки (по умолчанию 0 — без лимита); выключить всё — `MEDIA_ENABLED=false` или в панели.

## Telegram

Стелла работает **одновременно в WhatsApp и в Telegram**: личка и группы, та же память, характер и умения
(ответы, стикеры, картинки, документы, мультики, голосовые, видео по ссылкам, напоминания, казино…).

1. В Telegram напиши **@BotFather** → `/newbot`, придумай имя и логин (на `bot`) — получишь токен.
2. Там же `/setprivacy` → выбери бота → **Disable** (иначе в группах она видит только сообщения, где её отметили
   через @ или ответили ей). Если бот уже в группах — удали и добавь заново.
3. Узнай свой id: напиши **@userinfobot**. Потом открой своего бота и нажми **Start** — иначе бот не сможет
   написать тебе первым (предупреждения о сбоях приходят туда, если WhatsApp не на связи).
4. На сервере в `.env`:
   ```
   TELEGRAM_BOT_TOKEN=токен_от_BotFather
   TELEGRAM_OWNER_ID=твой_id
   ```
   и `docker compose up -d --build`. В логе появится «Telegram: бот @… на связи».
5. Добавь бота в группу — и пиши «стелла, …», отмечай её через @ или отвечай на её сообщения. В личке отвечает всегда.

Сообщения забираются из Telegram сами (long polling) — открывать сервер в интернет не нужно. Пока только в
WhatsApp: управление группой (кик, админка, название) и своя аватарка. Ограничить группы —
`TELEGRAM_ALLOWED_CHATS` (id группы виден в логе: `docker compose logs bot | grep "Telegram: группа"`).
Бота может найти по @username кто угодно: в личке у каждого, кроме владельца, можно ограничить число сообщений в
сутки — `TELEGRAM_DM_PER_DAY` (по умолчанию 0 — без лимита; от лишних трат защищает `DAILY_BUDGET_USD`). Токен — только в `.env`, никому не показывай (если засветился — `/revoke` в @BotFather).

## Видео по ссылке (TikTok, YouTube)

Кто-то скинул в чат ссылку на ролик TikTok или YouTube (обычное видео, Shorts, youtu.be, vm.tiktok.com) — Стелла
сама скачивает его и присылает видео **ответом на это сообщение**. В обсуждение при этом не встревает; если её
попросили («стелла скачай …») и не вышло — коротко скажет почему.

- Качает yt-dlp в отдельном процессе, по одному ролику за раз; разрешены только TikTok и YouTube.
- Видео приводится к тому, что WhatsApp точно покажет: MP4 (H.264 + AAC), до 720p, не больше `VIDEO_DL_MAX_MB` (30)
  МБ — большое пережимается; длиннее `VIDEO_DL_MAX_SECONDS` (5 минут) не качает.
- Лимиты считают попытки: `VIDEO_DL_PER_DAY` (30) на чат в сутки, 10 на человека, 300 на весь бот; одна и та же
  ссылка (даже с другим `?si=…`) в течение 10 минут — один раз. Выключить — `VIDEO_DL_ENABLED=false` или в панели.

**Если сайт не пускает сервер.** YouTube часто блокирует серверы дата-центров («Sign in to confirm you're not a
bot»), TikTok иногда блокирует IP. Стелла тогда напишет владельцу. Для YouTube помогает файл cookies:
1. В браузере на компьютере войди в YouTube (лучше второстепенным аккаунтом).
2. Поставь расширение «Get cookies.txt LOCALLY» и выгрузи cookies для youtube.com (формат Netscape).
3. Положи файл на сервер как `stella-bot/data/cookies.txt` (или укажи путь в `VIDEO_DL_COOKIES`) — перезапуск не нужен.

Сайты часто меняются; если скачивание сломалось у всех ссылок — обновить yt-dlp: поменять версию в
`requirements.txt` на свежую и `docker compose up -d --build`.

## Голосовые

Стелла **слышит** голосовые (расшифровывает их и дальше понимает как обычный текст, в том числе обращение «стелла…»)
и может **ответить голосом**, если попросить. Всё работает прямо на сервере и бесплатно: распознавание — faster-whisper,
голос — piper (русский голос «Ирина»). Модели скачиваются сами при первом голосовом (≈150–460 МБ) в `data/models`.

- Память: `VOICE_STT_MODEL=base` — около 0.3 ГБ (по умолчанию), `small` — точнее, около 0.6 ГБ (для сервера от 4 ГБ).
  Без голосовых модели через 30 минут выгружаются из памяти.
- Голосовые длиннее `VOICE_MAX_SECONDS` (3 мин) не расшифровываются.
- Не нужно совсем — `WITH_VOICE=false` в `.env` и `docker compose up -d --build` (образ меньше на ~480 МБ),
  или выключить в панели.

## Панель управления (сайт)

Сайт: **https://a1x10.github.io/project3/** (GitHub Pages) — или прямо на сервере: `http://localhost:18000/panel/` через SSH-туннель.
В панели: статус и расходы, все чаты (пауза, режим, «пусть сама напишет», отправить от её имени, переписка, «про чат»), анкеты людей (правка), настройки на лету (модель, лимиты, файлы, поиск…), журнал.

**Включить (один раз):**

1. Пароли — только в `.env` на сервере (в репозиторий их класть нельзя: он публичный):
   ```
   PANEL_PASSWORD_1=...
   PANEL_PASSWORD_2=...
   COMPOSE_PROFILES=panel
   ```
2. `docker compose up -d --build` — поднимется и туннель Cloudflare (бесплатно, без домена). Стелла сама пришлёт владельцу (`OWNER_PHONE`) в WhatsApp ссылку на панель с адресом туннеля. Узнать адрес вручную: `docker compose logs tunnel | grep trycloudflare`. После перезапуска туннеля адрес меняется — придёт новая ссылка.
3. GitHub Pages (один раз): репозиторий → **Settings → Pages → Build and deployment → Deploy from a branch** → ветка `claude/zealous-curie-yb4gpe`, папка `/docs` → **Save**. Через минуту сайт откроется по адресу выше.

**Защита:** вход по двум паролям, которые проверяются только на сервере и только вместе (какой из них неверный — не сообщается, по отдельности не подобрать). Каждая попытка ~1 с; 5 ошибок с одного адреса — блок 15 мин (дальше вдвое дольше); 20 ошибок за час со всех адресов — вход закрыт для всех на час. О каждом входе и блокировке приходит сообщение в WhatsApp. Сессия — случайный токен, только в памяти сервера, 8 ч максимум и 30 мин без действий; «Выйти везде» — в настройках. Запросы — только с сайта панели (CORS), страница запрещает чужие скрипты и встраивание (CSP), туннель — только HTTPS. Короткие пароли из цифр — слабое место: лучше длиннее.

## Написать человеку от лица Стеллы

Владелец (и `ADMIN_PHONES`) просит: «стелла, напиши +7 701 555 44 33, что можем сделать ему сайт» — Стелла сама составит сообщение от своего лица (представится ИИ-ассистентом, пишет по просьбе владельца), отправит и расскажет, что написала. Ответит человек — она помнит, зачем писала, продолжает разговор по делу, а владельцу приходит «📩 … ответил(а)».

- WhatsApp — по номеру или человеку из базы; Telegram — только тем, кто уже писал боту (первым бот в Telegram писать не может).
- Не больше `OUTREACH_PER_DAY` (20) сообщений в сутки — за массовые сообщения WhatsApp банит номер; одному человеку второй раз подряд — только после ответа или через сутки.
- Только по сообщению самого владельца: текст из файла или ссылки не заставит Стеллу никому писать.

## Розыгрыш (страница + рассылка в Telegram)

Страница для участников — `https://<адрес туннеля>/giveaway/`: имя, ник в Telegram или телефон, согласие → вопрос на сообразительность за 25 секунд → почта по желанию → номер участника. Одна заявка на контакт; данные — в `data/giveaway.db` и никуда не уходят.

**Как провести:**

1. Нужна внешняя ссылка: туннель (`COMPOSE_PROFILES=panel` в `.env`, как для панели) или свой домен в `GIVEAWAY_PUBLIC_URL`.
2. Напиши Стелле **в личку** `/розыгрыш` (только владелец и `ADMIN_PHONES`; в WhatsApp или Telegram) — она пришлёт ссылку на страницу и **одноразовую ссылку в админку** (15 минут, никому не пересылай). Пароль не нужен.
3. В админке → «Рассылка в Telegram»: текст уже вписан, кнопка «Участвовать 🎁». «Пробное — только мне» пришлёт его тебе (`TELEGRAM_OWNER_ID`), «Разослать» — всем, кто сам писал Стелле в личку Telegram, и сразу запустит таймер на 30 минут (галочку можно снять). Каждый получает сообщение один раз за розыгрыш; под ним — кнопка «Не присылать такое» (отписка навсегда); заблокировавших бота пропускаем. У каждого кнопка ведёт по **своей подписанной ссылке**: заявка по ней привязывается к его Telegram (один человек — одна заявка, в админке метка «TG»). В WhatsApp рассылки нет — там за них банят номер.
4. Время вышло → «Закрыть регистрацию» → «🎲 Выбрать победителя» (случайно, криптостойко; галочка «Только из рассылки» — среди пришедших по своей кнопке: их не накрутить скриптом, капча — лишь «лежачий полицейский»; если заявок за минуту подозрительно много — Стелла напишет) → «Написать в Telegram» / «Позвонить» или письмо (кнопка «Открыть в почте»; отправка прямо из админки — если заданы `GIVEAWAY_SMTP_*`).
5. Следующий раз — «Новый розыгрыш»: список начнётся с нуля (старые заявки останутся в базе), рассылку можно сделать снова. CSV — кнопкой «Скачать CSV».

Выключить совсем: `GIVEAWAY_ENABLED=false`. Приз и заголовок: `GIVEAWAY_PRIZE`, `GIVEAWAY_TITLE` (приз можно поменять и в админке).

## Защита от бана

Подключение неофициальное — риск бана есть всегда. Что делает код:

- в WhatsApp в личку первой никому не пишет (кроме алертов владельцу), никаких рассылок (рассылка розыгрыша — только в Telegram); в группы, где она уже есть, изредка пишет сама (`INITIATIVE_PER_WEEK`, 0 — выключить);
- «прочитала» → «печатает…» по длине текста → короткие сообщения; задержки `REPLY_DELAY_*`;
- лимит `RATE_LIMIT_PER_MIN` (20) сообщений в минуту на чат;
- `alwaysOnline=false`, звонки отклоняются;
- если WhatsApp отвалился (`CONNECTION_UPDATE`) — пробует переподключиться, шлёт алерт на `ALERT_WEBHOOK_URL`, а когда вернётся — пишет владельцу.

Холодные рассылки — только с отдельного номера, не со Стеллы.

## Данные

База бота (`data/bot.db`, SQLite; для PostgreSQL поменяйте `DATABASE_URL`): `chats` (пауза, режим, заметки), `people` (имя, ник, номер), `members`, `facts` (что Стелла знает о человеке, по чатам), `messages` (история — последние `HISTORY_WINDOW` идут в контекст), `wallets` (бананы), `stickers`, `kv`. Заявки розыгрыша — отдельно, в `data/giveaway.db`. В логах номера маскируются: `+7 777 *** ** 12`. Ключи — только в `.env`.

## Разработка

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt pytest pytest-asyncio
pytest -q
```

Тесты гоняют весь путь «вебхук → решение → модель (фейк) → отправка (фейк Evolution)», казино, разбор ставок, стикеры, память, оба LLM-бэкенда.

### Отличия от исходного ТЗ

ТЗ было написано под бота-администратора для бизнеса (записи, прайс). Для Стеллы:

- группы **не игнорируются** — это основной режим; таблицы `businesses/bookings` заменены на `people/facts/wallets/stickers`; инструменты `get_info/get_free_slots/book/call_human` — на память и казино;
- история в модель идёт из нашей БД (последние сообщения чата), а не через `resume=session_id`: в группе Стелла должна видеть и те сообщения, на которые не отвечала, а сессия Agent SDK разрасталась бы и дорожала. Так оба бэкенда работают одинаково.
