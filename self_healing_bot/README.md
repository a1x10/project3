# Self-Healing Bot

Telegram-бот, который следит за твоим приложением на сервере и сам пытается его починить:

```
health-check каждые 15 с
   │  2 провала подряд
   ▼
🚨 алерт в Telegram → перезапуск (до 2 попыток; гасится всё дерево процессов, освобождается порт)
   │  не поднялось — или падает 3 раза за 10 минут («цикл падений»)
   ▼
🧠 ИИ получает последние логи + код файлов из трейсбека → присылает диагноз и патч
   │  ты читаешь diff и жмёшь «✅ Применить фикс»
   ▼
git checkout -b ai-hotfix/… → патч → проверка синтаксиса → commit → перезапуск
   ├─ поднялось → ✅ готово (по желанию — git push ветки для Pull Request)
   └─ не поднялось → откат: исходная ветка, hotfix-ветка удаляется, перезапуск на старом коде
```

Плюс консоль прямо в чате: `/cmd pm2 status`, `/logs`, `/status` с нагрузкой на сервер.

## Быстрый старт

```bash
cd self_healing_bot
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env      # заполни: токен, свой ID, папку проекта и команду запуска
python main.py
```

1. Создай бота у [@BotFather](https://t.me/BotFather) → токен в `TELEGRAM_BOT_TOKEN`.
2. Узнай свой Telegram ID (например, у [@userinfobot](https://t.me/userinfobot)) → `ADMIN_IDS`.
   Ещё вариант: бот отвечает чужим на `/start` их ID.
3. Напиши своему боту `/start` — без этого Telegram не даст боту писать тебе первым.
4. Ключ ИИ → `AI_API_KEY` (см. «Какой ИИ подключить»).

Нужен Python 3.10+ и Linux-сервер. Для проверки синтаксиса JS-фиксов нужен `node`.

## Настройка под твой стек

Режимов два — выбери один.

**Бот сам запускает приложение** (`APP_START_CMD`). Команда должна работать в foreground — без `&`, `-d`, `nohup`. Логи пишутся в `data/app.log`.

```ini
APP_DIR=/home/user/my-app
APP_START_CMD=npm start            # или: node server.js / python3 app.py / uvicorn main:app --port 3000
HEALTH_URL=http://127.0.0.1:3000/health
```

Если у приложения нет HTTP — `HEALTH_URL=tcp://127.0.0.1:5432` (проверка порта) или вообще ничего: тогда бот считает приложение живым, пока жив процесс.

**Процессом управляет pm2 / systemd / docker** (`APP_RESTART_CMD`):

| Чем запущено | APP_RESTART_CMD | Логи (APP_LOGS_CMD) |
|---|---|---|
| pm2 | `pm2 restart my-app` | `pm2 logs my-app --nostream --lines 300` |
| systemd | `sudo systemctl restart my-app` | `journalctl -u my-app -n 300 --no-pager` |
| Docker Compose | `docker compose restart app` | `docker compose logs --tail 300 app` |

Для этого режима обязателен `HEALTH_URL` или `HEALTH_CMD` (например, `systemctl is-active --quiet my-app`).
Для `sudo systemctl` разреши боту эту команду без пароля через `visudo`. В Docker пути в трейсбеках
(`/usr/src/app/server.js`) бот сам сопоставит с файлами в `APP_DIR`.

Все остальные настройки (интервалы, пороги, git, лимиты для ИИ) описаны в [`.env.example`](.env.example).

## Какой ИИ подключить

| Провайдер | Настройки | Заметки |
|---|---|---|
| **Claude** (по умолчанию) | `AI_PROVIDER=anthropic`, `AI_API_KEY=sk-ant-…` | Модель `claude-opus-5-5`. JSON-ответ гарантирован structured outputs, включён серверный fallback на другую модель, если Claude откажется отвечать. Дешевле: `AI_MODEL=claude-sonnet-5-5`. Ключ: [console.anthropic.com](https://console.anthropic.com) |
| OpenAI | `AI_PROVIDER=openai`, `AI_API_KEY=sk-…`, `AI_MODEL=gpt-4o-mini` | |
| Google Gemini | `AI_PROVIDER=openai`, `AI_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai` | есть бесплатный тариф |
| Groq | `AI_PROVIDER=openai`, `AI_BASE_URL=https://api.groq.com/openai/v1` | есть бесплатный тариф |
| Ollama (локально) | `AI_PROVIDER=openai`, `AI_BASE_URL=http://127.0.0.1:11434/v1` | бесплатно, код не покидает сервер; маленьким моделям уменьши `AI_MAX_FILE_CHARS` |
| Без ИИ | `AI_PROVIDER=none` | только мониторинг и рестарты |

Любой другой OpenAI-совместимый API (OpenRouter, DeepSeek, LM Studio…) подключается так же — через `AI_BASE_URL`.

## Команды

| Команда | Что делает |
|---|---|
| `/status` | состояние приложения, последняя проверка, аптайм, CPU/RAM/диск |
| `/logs [N]` | последние N строк логов (длинные — файлом) |
| `/restart` | перезапустить и дождаться health-check |
| `/debug` | ИИ-анализ текущих логов, даже если приложение работает |
| `/pause`, `/resume` | выключить мониторинг на время деплоя |
| `/cmd <команда>` | выполнить команду в `APP_DIR`, например `/cmd git log -3`, `/cmd npm install` |

У алертов есть кнопки «🔄 Перезапустить», «📜 Логи», «🧠 ИИ-анализ».

## Безопасность

- **Бот управляет сервером**, поэтому `ADMIN_IDS` обязателен: всем остальным бот не отвечает (кроме подсказки с их ID на `/start`), и нажимать кнопки они тоже не могут.
- `/cmd` — это полноценный shell от имени пользователя, под которым запущен бот. Запускай бота **не от root**, а от отдельного пользователя. Выключить консоль: `SHELL_ENABLED=false`.
- ИИ ничего не применяет сам — только после твоей кнопки. Перед этим бот проверяет патч: файл внутри `APP_DIR`, это не `.env`, `.git` или `node_modules`, ИИ видел этот файл, а заменяемый фрагмент встречается в нём ровно один раз. После патча — проверка синтаксиса (Python, JS, JSON) и `FIX_CHECK_CMD`, если задана.
- В логах может оказаться текст от посторонних (например, URL запроса), который пытается «уговорить» ИИ. **Всегда читай diff, прежде чем жать «Применить».**
- Что уходит во внешний API: последние строки логов (токены, пароли и ключи в них маскируются), файлы из трейсбека и список файлов проекта. `.env` не отправляется никогда, но секреты, вписанные прямо в код, уйдут вместе с файлом — держи их в `.env`. Если код не должен покидать сервер, используй локальную Ollama.

## Запуск на сервере

Проще всего — в `tmux`: `tmux new -s bot`, затем `python main.py`. Надёжнее — systemd: готовый юнит лежит в [`deploy/self-healing-bot.service`](deploy/self-healing-bot.service).

В режиме `APP_START_CMD` приложение продолжает работать, когда останавливается сам бот, а новый экземпляр бота подхватит его по PID-файлу (`data/app.pid`), не запуская вторую копию.

После успешного фикса сервер работает на ветке `ai-hotfix/…`. Влей её в основную ветку (или включи `GIT_PUSH=true` и открой Pull Request), а потом верни сервер на основную ветку.

## Попробовать на demo-приложении

```bash
cp -r demo_app /tmp/demo && cd /tmp/demo
git init -q && git add . && git commit -qm init
```

В `.env` бота: `APP_DIR=/tmp/demo`, `APP_START_CMD=python3 server.py`, `HEALTH_URL=http://127.0.0.1:3000/health`.
Запусти бота, затем «сломай» приложение: в `/tmp/demo/server.py` замени `load_config()` на `load_confg()`,
сделай коммит и нажми `/restart`. Приложение упадёт при старте, бот попробует его поднять, позовёт ИИ
и пришлёт патч с кнопкой «Применить».

## Что исправлено по сравнению с исходной схемой

Идея исходной схемы хорошая, но код из неё на практике либо не работал, либо был опасен:

| Было | Проблема | Стало |
|---|---|---|
| `client.post("https://openai.com", …)` | это адрес сайта, а не API — запрос никогда бы не сработал | официальный SDK Anthropic или правильный `/v1/chat/completions` |
| ИИ видит только логи, но должен вернуть «весь исправленный файл» | модель не видела файл — она бы его выдумала и затёрла твой код | ИИ получает код из трейсбека и возвращает точечные правки search/replace, бот их проверяет |
| путь от ИИ сразу идёт в `open(file, "w")` и `git add {file}` с `shell=True` | ИИ (или текст в логах) мог переписать любой файл на сервере или выполнить команду | путь только внутри `APP_DIR`, git вызывается без shell |
| `try_restart()` возвращает `True` сразу после `Popen` | рестарт «успешен», даже если приложение тут же упало; откат фикса никогда не срабатывал, а сломанный фикс уходил в GitHub | ждём, пока ответит health-check; падение при старте видно сразу |
| `handle_failure` на каждой проверке | пока приложение лежит — алерт и рестарт каждые 15 секунд | порог ошибок, один алерт на инцидент, напоминания, детектор цикла падений |
| `subprocess.run` внутри async-кода | бот «замерзал» на время команд | всё асинхронно |
| `fuser -k 3000/tcp`, `open("server.log")` на каждый рестарт | убивается только тот, кто держит порт: зависшая до открытия порта копия живёт рядом с новой; файлы логов не закрываются | гасится вся группа процессов приложения; порт освобождается только от процессов из папки проекта |
| кнопка `callback_data="apply_fix"` | обработчика нет, фикс нигде не сохранён, кнопку мог нажать любой в чате | у фикса свой ID, только для админов, повторное нажатие ничего не делает |
| `git checkout -b ai-hotfix-branch` без проверки результата | со второго раза ветка уже существует, команда падает молча — и фикс коммитится прямо в текущую ветку; файл перезаписывается вместе с твоими незакоммиченными правками | уникальные ветки, каждый шаг git проверяется, файлы с незакоммиченными правками не трогаются |
| `parse_mode="MarkdownV2"` и `**жирный**` | вывод с `` ` `` или `\` внутри блока кода Telegram отклонит; в остальных сообщениях разметка не включена, и `**жирный**` виден звёздочками | HTML с экранированием, длинный вывод — файлом |
| `/cmd` без таймаута, `stdout or stderr`, `message.text[5:]` | `tail -f` вешал обработчик навсегда, ошибки терялись, `/cmd@BotName` ломался | таймаут с убийством дерева процессов, оба потока вывода, нормальный разбор команды |
| `asyncio.create_task(...)` без ссылки и без `try` | задачу может собрать сборщик мусора, а одна сетевая ошибка навсегда убивала мониторинг | ссылка на задачу хранится, ошибки логируются, цикл продолжается |
| ловятся только `ConnectError` и `TimeoutException` | `RemoteProtocolError`, `ReadError` и т. п. роняли мониторинг | ловится любая `httpx.HTTPError` |
| токены и ключи прямо в коде | утекут в git | `.env` |
| «проверить синтаксис перед перезапуском» | обещано в тексте, но не сделано | `compile()` для Python, `node --check` для JS, JSON, плюс своя команда `FIX_CHECK_CMD` |

## Устройство

| Файл | Что внутри |
|---|---|
| `main.py` | точка входа: бот aiogram + фоновый мониторинг |
| `config.py` | настройки из `.env` с проверкой |

| `agent.py` | ИИ: сбор контекста, запрос к модели, проверка патча (шаг 3) |
| `git_patch.py` | применение фикса через git с откатом (шаг 4) |
| `handlers.py` | команды и кнопки Telegram (шаг 5) |
| `telegram_ui.py` | оформление сообщений и отправка алертов |
| `shell.py` | безопасный запуск команд с таймаутом |

## Тесты

```bash
pip install -r requirements-dev.txt
python -m pytest
```

Тесты не ходят ни в Telegram, ни в API ИИ: процессы, порты и git — настоящие, а Telegram и модель подменены.
Сквозной тест `tests/test_e2e.py` проходит весь путь: деплой с опечаткой → падение → рестарт не помог →
ИИ получил трейсбек и код → «Применить» → ветка, коммит, приложение снова отвечает.
