# Stella Cloud

Сервер для Stella: агент работает, даже когда компьютер выключен; приложение для телефона; перенос задач ПК ↔ сервер; WhatsApp для агента.

## Установка на сервер (Ubuntu / Debian)

```bash
curl -fsSL https://raw.githubusercontent.com/a1x10/project3/claude/happy-ritchie-vx32ws/stella-cloud/install.sh | sudo bash
```

Скрипт ставит Node.js 22, Antigravity CLI (`agy`), сам сервер (systemd-служба `stella-cloud`) и HTTPS через Caddy.
В конце он печатает адрес (по умолчанию `https://<ip-сервера>.sslip.io`) и **код приглашения**.
Свой домен: `DOMAIN=stella.example.com` перед `bash`. Обновление — та же команда.

Порты 80 и 443 должны быть открыты (для HTTPS-сертификата Let's Encrypt). Если на сервере уже есть nginx — установщик добавит в него отдельный сайт и получит сертификат через certbot, ничего не трогая.

**Свой адрес через DuckDNS** (бесплатно): зарегистрируйтесь на duckdns.org, создайте имя (например `mystella`) и запустите:

```bash
curl -fsSL https://raw.githubusercontent.com/a1x10/project3/claude/happy-ritchie-vx32ws/stella-cloud/install.sh | sudo DUCKDNS=mystella bash
```

Токен DuckDNS установщик спросит скрыто. IP обновляется каждые 5 минут. Адрес станет `https://mystella.duckdns.org`.


## Как пользоваться

1. **Телефон.** Откройте адрес сервера → «Регистрация» (имя, пароль, код приглашения) → «Добавить на главный экран».
   Для каждого аккаунта создаётся отдельный Linux-пользователь `st_<имя>` со своей папкой и своим агентом.
2. **Вход агента в Google** (один раз): «Ещё» → «Открыть терминал агента» → откройте ссылку, войдите, вставьте код.
3. **Компьютер.** Stella → «Облако» (слева внизу) → адрес сервера, имя, пароль.
   Теперь с телефона видно, что делает агент на ПК, можно дать ему задачу и нажать «→ Сервер», чтобы задача продолжилась на сервере (и обратно «→ Компьютер»). На ПК есть кнопка «↗ На сервер».
4. **WhatsApp.** Вкладка WhatsApp → «Подключить по QR-коду» → WhatsApp на телефоне → Связанные устройства.
   - Агент пишет людям **только когда вы просите**: «напиши жене, во сколько ужин» → он находит контакт, пишет в вашем стиле, ответ приходит вам в чат и уведомлением.
   - **Автоответчик** включается отдельно для каждого контакта (переключатель в списке). Не отвечает на вопросы про деньги/встречи/то, чего не знает; не больше 40 ответов в день на контакт; всё пишется в журнал.
   - ⚠️ Это неофициальное подключение (протокол WhatsApp Web, библиотека Baileys). WhatsApp может заблокировать номер за автоматизацию.

## Настройки

`/etc/stella-cloud.env`:

| Переменная | Значение |
|---|---|
| `STELLA_SIGNUP` | `invite` (по коду, по умолчанию), `open`, `closed` |
| `STELLA_INVITE` | код приглашения |
| `STELLA_WA_PROXY` | прокси для WhatsApp, если сервер выходит в интернет только через прокси |

После изменения: `systemctl restart stella-cloud`. Логи: `journalctl -u stella-cloud -f`.

## Если на компьютере пропал свет

Пока на ПК идёт задача, Stella раз в 3 минуты отправляет на сервер снимок папки проекта (без `node_modules`, `dist` и т. п., до 300 МБ).
Сервер каждые 15 секунд проверяет, жив ли ПК. Если ПК пропал посреди задачи и не вернулся за 45 секунд — сервер распаковывает снимок
в контейнер этого аккаунта и **доделывает задачу сам**, с полной историей. На телефон приходит уведомление «⚡ задача продолжена на сервере».
Когда ПК включится, Stella покажет это в чате и кнопку **«⬇ Забрать файлы с сервера»** — результат скачается в отдельную папку
`<проект>-с-сервера-<дата>`, ваши файлы не перезаписываются.

Чтобы снимки работали, выберите в Stella слева **папку проекта** (а не весь профиль).

## Защита (что включено и как усилить)

Включено всегда:
- пароли: scrypt + соль, минимум 10 символов, проверка простых паролей; **блокировка аккаунта** после 5 неверных попыток (15 мин, дальше дольше);
- **двухфакторная защита** (Google Authenticator / Aegis / 1Password): телефон → «Ещё» → «Безопасность»;
- сессии хранятся только как хеши, истекают через 30 дней бездействия, список устройств и «Выйти на всех устройствах», уведомление о каждом новом входе;
- лимиты запросов по IP (nginx + сервер), подделка X-Forwarded-For не помогает; журнал входов: `/var/lib/stella/security.log`;
- заголовки безопасности (CSP, HSTS, запрет фреймов), версия nginx скрыта;
- контейнеры агентов в отдельной сети: не видят сервер, соседей, внутренние адреса и метаданные Hetzner.

Капча Cloudflare Turnstile (бесплатно): dash.cloudflare.com → Turnstile → Add widget → домен `stellalive.duckdns.org` → получите Site Key и Secret Key, затем:
```bash
curl -fsSL https://raw.githubusercontent.com/a1x10/project3/claude/happy-ritchie-vx32ws/stella-cloud/install.sh | sudo DUCKDNS=stellalive TURNSTILE=1 bash
```

Защита самого сервера (файрвол, fail2ban, SSH, автообновления) — интерактивно, с вопросами:
```bash
curl -fsSL https://raw.githubusercontent.com/a1x10/project3/claude/happy-ritchie-vx32ws/stella-cloud/scripts/harden.sh | sudo bash
```

Спрятать сервер и защититься от DDoS — Cloudflare Tunnel (нужен свой домен в Cloudflare; DuckDNS по своей природе показывает IP):
Cloudflare → Zero Trust → Networks → Tunnels → Create → скопируйте токен →
```bash
curl -fsSL https://raw.githubusercontent.com/a1x10/project3/claude/happy-ritchie-vx32ws/stella-cloud/install.sh | sudo TUNNEL=stella.вашдомен.com bash
```
затем в туннеле Public Hostname: `stella.вашдомен.com` → `http://localhost:<порт Stella>`. Stella перестаёт быть доступной по IP вообще.

## Безопасность

- **Каждый аккаунт работает в своём Docker-контейнере** (`stella-<имя>`): не root, без Linux-привилегий (`--cap-drop ALL`, `no-new-privileges`), лимиты памяти/CPU/процессов, примонтирована только его домашняя папка. Docker-сокет, настройки сервера и код Stella внутри не видны — агент не может «попросить систему» что-то сделать.
- Если Docker недоступен — запасной режим: отдельный Linux-пользователь + лимиты systemd.
- Сама служба работает от root (создаёт пользователей и контейнеры).
- HTTPS (Let's Encrypt) + HSTS: браузер открывает сайт только по HTTPS — это и защищает от перехвата.
- На сервере агент по умолчанию работает в режиме «Полный автомат» (подтверждать действия некому) — внутри своего пользователя. Режим меняется в «Ещё».
- Переписки WhatsApp хранятся только на вашем сервере: `/var/lib/stella/users/<имя>/whatsapp/`.
